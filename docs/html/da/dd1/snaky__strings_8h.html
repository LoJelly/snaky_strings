Represents a list of attributes collected from an attribute string.

Note
Similar to snaky_attrib_maps, snaky_attrib_lists contain info about the attributes in a string. However, entry lists do not contain key:value pairs, and instead all the entries collected are stored in a sequential order. They also contain more information, such as the data type of the attribute.

enum snaky_fwrite_mode

Determines how data should be written to a file.

Enumerator
SNAKY_FWRITE_BINARY 

The default write mode.

This results in all data being written in binary format.

SNAKY_FWRITE_TEXT 

Results in plain text being written to the file.

Important
When using snaky_write_file_data(...) with SNAKY_FWRITE_TEXT, each entry in the map is written in its own attribute string. For example, if the map contains 2 entries, they are written as 2 individual attribute strings even if they may be in the same string originally. This is because snaky_attrib_maps only know about the entries, and nothing about the starting and ending positions in attribute strings. If you want to preserve the actual attribute strings, use snaky_write_file_str(...) instead.
SNAKY_FWRITE_ENCRYPT 

Results in non-string values being written in binary format, and strings will be encrypted.

◆ snaky_goto_label()

SNAKY_API void snaky_goto_label ( const char * str,
const char * label_name,
const char ** out_pos )

Finds the given label within an attribute string and returns the position of it.

Labels are used to organize and navigate large files more easily.

Labels are expected to be on a single line, with no characters before or after the label's name. A label is created like this:

"/[ LABEL NAME ]/"

A full example of a label looks like this:

" /[ Generic Options ]/ <x = y> "

Note
For the 'label_name' parameter, you do not have to include the "/[" or "]/" characters, just the name of the label. In the example above, the label name string would just be "Generic Options."

When using this function to go to the 'Generic Options' label, the returned character is the '<.'

If 'out_pos' is NULL, the function will not do anything. Othwerise, it will be equal to the pointer to the first character after the label, or NULL if the label was not found.

Searches the given string for the very next attribute and tries to parse its value.

Note
Because this function parses the next attribute found, two buffers are required; one for the name of the attribute parsed, as well as one for its value.

To automatically walk a string and its attributes, pass a pointer into 'out_start_pos' and then on the next call use 'out_start_pos' as the 'str' attribute string.

Important
When data types are parsed within a string, it can go 2 routes. The first route is the explicit route: this means the user directly placed a ':DATA_TYPE' part into the name of the attribute. The second route is the implicit route. The function will try to determine the type of the value. Because of this, it will never assume the SNAKY_DOUBLE or SNAKY_CHAR types. It can only ever assume SNAKY_BOOL, SNAKY_INT, or SNAKY_FLOAT.

◆ snaky_parse_target_attrib_buf()

SNAKY_API int snaky_parse_target_attrib_buf ( const char * str,
char * buffer,
size_t buffer_size,
const char * attrib_name,
const char ** out_start_pos,
snaky_data_type * out_data_type )

Searches the given string for a specific attribute and tries to parse its value.

Examples:

The attribute string is: '<id=obj4,x=20,y=300>'

The attribute list will consist of 'id,' 'x,' and 'y.'

The value list will consist of 'obj4,' '20,' and '300.'

Attributes must be separated by the ',' character, and they must be assigned using the '=' character.

Important
All attribute strings should be char arrays, unless you do not plan on modifying the string, then it can be a const char*.
Note
Whitespace is allowed in attribute strings. These two strings are equal when parsed: '<id=obj4,x=20,y=300>' and '< id = obj4, x = 20, y = 300 >'

When attempting to place a nested attribute string inside of another attribute string, the nested attribute string MUST be surrounded by '"' characters. So the proper way to write it would look like this:

'<attrib_string="<...>">'

Also, any attributes surrounded by the '"' character are treated as string literals and are copied exactly as they are typed. If any strings in the attribute list contain nested attribute lists, they are not parsed. Strings are skipped during the parsing stage. There is an exception to this rule however: if you are specifically attempting to find a nested attribute, you can chain together the outer names to piece the path together. For example, in this string:

'<player="<name=PLAYER1>">'

The 'name' attribute can be accessed using 'player.name' as the target name. Note that this only works for nested attribute strings. Additionally, if multiple strings are nested, the names can be chained, like this 'v1.v2.v3...'

Parameters
strThe string to search.
bufferWhere to place the value of the found attribute. If this is NULL, then the function will only return whether or not the attribute was found.
buffer_sizeThe size of 'buffer' in bytes.
attrib_nameThe name of the attribute to search for.
out_start_posA pointer to a const char*. If a valid pointer is given, it will be equal to the position in the original string where the next attribute starts. Specifically, it will point to the first character in the next attribute name found. If no next attribute is found, then the pointer will be equal to NULL.
out_data_typeA pointer to a snaky_data_type. If a valid pointer is given, it will be equal to the data type of the parsed attribute.
Returns
1 if the attribute was successfully parsed/found, 0 if the function fails in any way.

SNAKY_API int snaky_set_attribs_buf ( char * str,
size_t buffer_size,
const char * attribs )

Modifies multiple attribute values directly in a string.

To set multiple attributes, the 'attribs' string must be formatted like this:

"<attrib_name=new_attrib_value,attrib_name2=new_attrib_value,...>"

For example, using this attribute string:

"<x=100,y=200>"

To set both the 'x' and 'y' attributes at the same time, the function would be called like this:

'snaky_set_attribs(str, sizeof(str), "<x=300,y=150>");'

Returns
1 on success, 0 on failure.
